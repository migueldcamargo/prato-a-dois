Prato a Dois · guia de implantação

Do zero ao app no celular em cerca de 30 minutos. Tudo no plano grátis.

0 de 0 passos

Marque cada passo quando terminar. O progresso fica salvo neste navegador, então dá para parar e voltar depois.

O que veio no zip
  • Os arquivos do app: index.html, logica.js, config.js, manifest.webmanifest, sw.js e os ícones .png. É isso que vai para o GitHub (o repositório oficial já tem tudo, inclusive as pastas docs e dev).
  • supabase.sql: o banco de dados. Ele também está no passo 1.4 com botão de copiar.
  • Este guia.

Faça as partes 1 e 2 num computador. A parte 3 é no celular.

Parte 1 · Banco de dados no Supabasecerca de 10 minutos

1.1Crie uma conta no GitHub (se ainda não tiver)

  1. Acesse github.com/signup.
  2. Preencha e-mail, senha e um nome de usuário. Guarde o nome de usuário: ele vai aparecer no link do app.
  3. Confirme o código que chega por e-mail.

Você vai usar essa mesma conta para entrar no Supabase.

1.2Entre no Supabase com o GitHub

  1. Acesse supabase.com/dashboard.
  2. Clique em Continue with GitHub e autorize.
  3. Se pedir para criar uma organização: dê qualquer nome (ex.: Miguel), tipo Personal, plano Free, e clique em Create organization.

1.3Crie o projeto

  1. Clique em New project.
  2. Project name: prato-a-dois.
  3. Database Password: clique em Generate a password e guarde a senha num lugar seguro. O app não usa essa senha, mas ela é sua chave mestra do banco.
  4. Region: South America (São Paulo).
  5. Clique em Create new project e espere uns 2 minutos até o painel do projeto aparecer.

1.4Crie as tabelas: cole o SQL e rode

  1. No menu da esquerda, clique em SQL Editor.
  2. Clique em + ou New query para abrir uma consulta em branco.
  3. Clique em Copiar SQL aqui embaixo, cole no editor (Ctrl+V ou Cmd+V) e clique em Run.
  4. Se aparecer um aviso de “destructive operation”, confirme em Run this query. É só porque o script recria as regras de acesso; nenhum dado é apagado.

--  Como usar: no Supabase, abra "SQL Editor", cole TUDO e clique em "Run".
--  Pode rodar de novo sem medo: o script não apaga dados existentes.
--  Para atualizar de uma versão anterior, é só rodar este arquivo inteiro de novo.
--
--  Mudou algo aqui? Suba o número em versao_banco() (seção 6) e, se o app
--  depender da mudança, o BANCO_VERSAO_MIN em index.html.
--  Histórico:  v1 · estrutura inicial
--              v2 · opção "ambos" (os dois) nos atributos; transições de papel explícitas

-- Um cardápio por casal. O código tem 5 caracteres, sem 0, O, 1, I e L.
create table if not exists public.cardapios (
  codigo     text primary key check (codigo ~ '^[A-HJKMNP-Z2-9]{5}$'),
  nome       text not null check (char_length(nome) between 1 and 40),
  dono       uuid not null,
  criado_em  timestamptz not null default now()
);

-- Quem participa de cada cardápio e com qual papel.
create table if not exists public.membros (
  cardapio   text not null references public.cardapios(codigo) on delete cascade,
  user_id    uuid not null,
  nome       text not null default 'Alguém' check (char_length(nome) between 1 and 30),
  papel      text not null default 'leitor' check (papel in ('dono', 'editor', 'leitor', 'pendente')),
  criado_em  timestamptz not null default now(),
  primary key (cardapio, user_id)
);
create index if not exists membros_user_idx on public.membros (user_id);

-- Categorias de cada cardápio (as 14 iniciais são criadas junto com o cardápio).
create table if not exists public.categorias (
  id         uuid primary key default gen_random_uuid(),
  cardapio   text not null references public.cardapios(codigo) on delete cascade,
  nome       text not null check (char_length(nome) between 1 and 24),
  icone      text not null default '🍴',
  ordem      int  not null default 0,
  criado_em  timestamptz not null default now()
);
create unique index if not exists categorias_nome_unico on public.categorias (cardapio, lower(nome));

-- Pratos. Os 4 atributos do quiz são opcionais (null = sem resposta; 'ambos' = os dois).
create table if not exists public.pratos (
  id            uuid primary key default gen_random_uuid(),
  cardapio      text not null references public.cardapios(codigo) on delete cascade,
  nome          text not null check (char_length(nome) between 1 and 60),
  origem        text not null check (origem in ('casa', 'restaurante')),
  restaurante   text not null default '' check (char_length(restaurante) <= 50),
  categorias    uuid[] not null default '{}',
  tempo         text check (tempo   in ('rapido', 'elaborado', 'ambos')),
  peso          text check (peso    in ('leve', 'encorpado', 'ambos')),
  sabor         text check (sabor   in ('salgado', 'doce', 'ambos')),
  ocasiao       text check (ocasiao in ('diadia', 'especial', 'ambos')),
  criado_por    uuid not null default auth.uid(),
  criado_em     timestamptz not null default now(),
  atualizado_em timestamptz not null default now(),
  unique (id, cardapio)
);
create index if not exists pratos_cardapio_idx on public.pratos (cardapio);

-- v2: bancos criados na v1 ganham a opção 'ambos' nos 4 atributos (refaz as regras de valor).
alter table public.pratos drop constraint if exists pratos_tempo_check;
alter table public.pratos add  constraint pratos_tempo_check   check (tempo   in ('rapido', 'elaborado', 'ambos'));
alter table public.pratos drop constraint if exists pratos_peso_check;
alter table public.pratos add  constraint pratos_peso_check    check (peso    in ('leve', 'encorpado', 'ambos'));
alter table public.pratos drop constraint if exists pratos_sabor_check;
alter table public.pratos add  constraint pratos_sabor_check   check (sabor   in ('salgado', 'doce', 'ambos'));
alter table public.pratos drop constraint if exists pratos_ocasiao_check;
alter table public.pratos add  constraint pratos_ocasiao_check check (ocasiao in ('diadia', 'especial', 'ambos'));

-- Fotos ficam numa tabela à parte (texto base64, máx. ~300 KB) para a lista de pratos carregar rápido.
create table if not exists public.fotos (
  prato_id      uuid primary key,
  cardapio      text not null,
  data          text not null check (data like 'data:image/%' and char_length(data) < 400000),
  atualizado_em timestamptz not null default now(),
  foreign key (prato_id, cardapio) references public.pratos (id, cardapio) on delete cascade
);
create index if not exists fotos_cardapio_idx on public.fotos (cardapio);

-- Nota de cada pessoa para cada prato (1 a 5).
create table if not exists public.notas (
  prato_id      uuid not null,
  cardapio      text not null,
  user_id       uuid not null default auth.uid(),
  nota          int  not null check (nota between 1 and 5),
  atualizado_em timestamptz not null default now(),
  primary key (prato_id, user_id),
  foreign key (prato_id, cardapio) references public.pratos (id, cardapio) on delete cascade
);
create index if not exists notas_cardapio_idx on public.notas (cardapio);

-- Cada "Fizemos hoje" / "Pedimos hoje".
create table if not exists public.feitos (
  id         uuid primary key default gen_random_uuid(),
  prato_id   uuid not null,
  cardapio   text not null,
  data       date not null default current_date,
  por        uuid not null default auth.uid(),
  criado_em  timestamptz not null default now(),
  foreign key (prato_id, cardapio) references public.pratos (id, cardapio) on delete cascade
);
create index if not exists feitos_cardapio_idx on public.feitos (cardapio);

-- 2. Funções de apoio para as regras de acesso
-- ---------------------------------------------------------------------

create or replace function public.e_membro(p_cardapio text) returns boolean
language sql stable security definer set search_path = public as $$
  select exists (select 1 from public.membros where cardapio = p_cardapio and user_id = auth.uid());
$$;

create or replace function public.pode_editar(p_cardapio text) returns boolean
language sql stable security definer set search_path = public as $$
  select exists (select 1 from public.membros
                 where cardapio = p_cardapio and user_id = auth.uid() and papel in ('dono', 'editor'));
$$;

create or replace function public.e_dono(p_cardapio text) returns boolean
language sql stable security definer set search_path = public as $$
  select exists (select 1 from public.membros
                 where cardapio = p_cardapio and user_id = auth.uid() and papel = 'dono');
$$;

-- Cria um cardápio com código único, a pessoa como dona e as categorias iniciais.
create or replace function public.criar_cardapio(p_nome text, p_meu_nome text) returns text
language plpgsql security definer set search_path = public as $$
declare
  v_codigo    text;
  v_chars     constant text := 'ABCDEFGHJKMNPQRSTUVWXYZ23456789';
  v_tentativa int := 0;
begin
  if auth.uid() is null then raise exception 'Sessão não encontrada.'; end if;
  loop
    v_tentativa := v_tentativa + 1;
    v_codigo := '';
    for i in 1..5 loop
      v_codigo := v_codigo || substr(v_chars, 1 + floor(random() * length(v_chars))::int, 1);
    end loop;
    begin
      insert into cardapios (codigo, nome, dono)
      values (v_codigo, left(coalesce(nullif(btrim(p_nome), ''), 'Nosso cardápio'), 40), auth.uid());
      exit;
    exception when unique_violation then
      if v_tentativa > 25 then raise; end if;
    end;
  end loop;

  insert into membros (cardapio, user_id, nome, papel)
  values (v_codigo, auth.uid(), left(coalesce(nullif(btrim(p_meu_nome), ''), 'Dono'), 30), 'dono');

  insert into categorias (cardapio, nome, icone, ordem)
  select v_codigo, c.nome, c.icone, c.ordem
  from (values ('Hambúrguer', '🍔', 1), ('Pizza', '🍕', 2), ('Massas', '🍝', 3), ('Risoto', '🍚', 4),
               ('Asiática', '🥢', 5), ('Japonesa', '🍣', 6), ('Churrasco', '🔥', 7), ('Carnes', '🥩', 8),
               ('Saladas', '🥗', 9), ('Wraps', '🌯', 10), ('Sopas', '🍲', 11), ('Lanches', '🥪', 12),
               ('Air fryer', '🍟', 13), ('Sobremesas', '🍰', 14)) as c (nome, icone, ordem);
  return v_codigo;
end $$;

-- Entra num cardápio pelo código (como leitor). Devolve null se o código não existe.
create or replace function public.entrar_cardapio(p_codigo text, p_meu_nome text) returns json
language plpgsql security definer set search_path = public as $$
declare
  v_card  cardapios;
  v_papel text;
begin
  if auth.uid() is null then raise exception 'Sessão não encontrada.'; end if;
  select * into v_card from cardapios where codigo = upper(btrim(p_codigo));
  if not found then return null; end if;
  insert into membros (cardapio, user_id, nome, papel)
  values (v_card.codigo, auth.uid(), left(coalesce(nullif(btrim(p_meu_nome), ''), 'Alguém'), 30), 'leitor')
  on conflict (cardapio, user_id) do nothing;
  select papel into v_papel from membros where cardapio = v_card.codigo and user_id = auth.uid();
  return json_build_object('codigo', v_card.codigo, 'nome', v_card.nome, 'papel', v_papel);
end $$;

-- Leitor pede para poder editar.
create or replace function public.pedir_edicao(p_codigo text) returns boolean
language plpgsql security definer set search_path = public as $$
begin
  update membros set papel = 'pendente'
  where cardapio = p_codigo and user_id = auth.uid() and papel = 'leitor';
  return found;
end $$;

-- Dono muda o papel de outra pessoa. Só valem estas transições (iguais a ACOES_PAPEL em logica.js):
--   aprovar      pendente → editor        recusar  pendente → leitor
--   tornar dono  editor   → dono          tirar edição  editor → leitor
--   remover      leitor   → (sai do cardápio)
-- Dono nunca é rebaixado nem removido por outra pessoa.
create or replace function public.definir_papel(p_codigo text, p_user uuid, p_papel text) returns boolean
language plpgsql security definer set search_path = public as $$
declare v_atual text;
begin
  if not public.e_dono(p_codigo) then raise exception 'Só o dono pode fazer isso.'; end if;
  if p_user = auth.uid() then raise exception 'Você não pode mudar o seu próprio papel.'; end if;
  select papel into v_atual from membros where cardapio = p_codigo and user_id = p_user for update;
  if not found then raise exception 'Essa pessoa não está neste cardápio.'; end if;
  if (v_atual, p_papel) not in (('pendente', 'editor'), ('pendente', 'leitor'),
                                ('editor', 'dono'), ('editor', 'leitor'),
                                ('leitor', 'remover')) then
    raise exception 'Mudança de papel não permitida: % para %.', v_atual, p_papel;
  end if;
  if p_papel = 'remover' then
    delete from membros where cardapio = p_codigo and user_id = p_user;
  else
    update membros set papel = p_papel where cardapio = p_codigo and user_id = p_user;
  end if;
  return true;
end $$;

-- Atualiza o nome da pessoa em todos os cardápios dela.
create or replace function public.renomear_me(p_nome text) returns void
language plpgsql security definer set search_path = public as $$
begin
  if nullif(btrim(p_nome), '') is null then return; end if;
  update membros set nome = left(btrim(p_nome), 30) where user_id = auth.uid();
end $$;

1.5Ligue o acesso sem login

O app não tem login: cada celular ganha uma identidade anônima. Isso precisa ser ligado:

  1. No menu da esquerda, clique em Authentication.
  2. Clique em Sign In / Providers.
  3. Ative Allow anonymous sign-ins.
  4. Clique em Save changes.
Se pular este passo, o app mostra a tela “Falta um ajuste no Supabase”.

1.6Copie a URL e a chave pública do projeto

  1. No topo do painel do projeto, clique em Connect.
  2. Copie a Project URL (algo como https://abcdefghijklmnop.supabase.co) e cole num bloco de notas.
  3. Copie a Publishable key (começa com sb_publishable_) e cole também.

Não achou o botão Connect? Vá em Project Settings (engrenagem) → API Keys para a chave, e em Data API para a URL. Em projetos antigos a chave pública se chama anon public: pode usar ela.

Nunca use a secret key (sb_secret_) nem a service_role. Elas ignoram as regras de acesso e não podem ir para o GitHub.

Parte 2 · Site no GitHub Pagescerca de 10 minutos

2.1Descompacte o zip no computador

Clique com o botão direito no zip e escolha Extrair tudo (Windows) ou dê dois cliques (Mac). Você vai usar a pasta site.

2.2Crie o repositório

  1. Entre em github.com/new.
  2. Repository name: prato-a-dois.
  3. Deixe marcado Public. O GitHub Pages grátis só funciona com repositório público. O código fica visível, mas os dados de vocês ficam protegidos no Supabase.
  4. Não marque README, .gitignore nem licença.
  5. Clique em Create repository.

2.3Envie os arquivos do app

  1. Na página do repositório vazio, clique no link uploading an existing file.
  2. Abra a pasta site no computador, selecione todos os arquivos de dentro dela (Ctrl+A ou Cmd+A) e arraste para a página. Arraste os arquivos, não a pasta.
  3. Espere todos os arquivos aparecerem na lista.
  4. Lá embaixo, clique em Commit changes.
Confira: a página do repositório precisa mostrar index.html direto na lista, não dentro de uma pasta site.

2.4Cole a URL e a chave no config.js

  1. No repositório, clique em config.js.
  2. Clique no ícone de lápis (Edit this file), no canto direito acima do código.
  3. Troque COLE_AQUI_A_PROJECT_URL pela Project URL e COLE_AQUI_A_PUBLISHABLE_KEY pela Publishable key. Mantenha as aspas.
  4. Clique em Commit changes... e depois em Commit changes de novo na janela que abrir.

  • Android: abra no Chrome.

3.2Adicione à tela de início

iPhone (Safari):

  1. Toque em ⋯ (três pontinhos) no canto de baixo, à direita. Se a barra mostrar o ícone de compartilhar (quadrado com seta), toque direto nele e pule o próximo item.
  2. Toque em Compartilhar.
  3. Toque em Adicionar à Tela de Início. Se não aparecer, toque em Ver mais ou role a lista.
  4. Deixe Abrir como App Web ligado e toque em Adicionar.

Android (Chrome):

  1. Toque em ⋮ (três pontinhos) no canto de cima, à direita.
  2. Toque em Instalar app (em alguns celulares: Adicionar à tela inicial).
  3. Confirme em Instalar.
No iPhone, instale antes de digitar o nome e criar o cardápio. O app instalado guarda os dados separado do Safari: o que for feito no Safari não aparece no app instalado.

Dá para ver esse tutorial de novo a qualquer hora: Configurações → Como instalar no celular.

3.3Crie o cardápio de vocês

  1. Abra o Prato a Dois pelo ícone na tela de início.
  2. Digite seu nome e toque em Começar.
  3. Toque em Criar cardápio novo, dê um nome e toque em Criar cardápio.
  4. Toque em Compartilhar (ou Enviar pelo WhatsApp) para mandar o link e o código de 5 caracteres para sua namorada.

3.4Libere a edição para o seu par

  1. Ela instala o app, digita o nome, toca em Entrar com código e digita o código.
  2. Ela entra como leitora e toca em Pedir para editar.
  3. No seu celular aparece o aviso de pedido. Toque nele (ou em Configurações) e em Aprovar.
  4. Recomendado: em Configurações → Pessoas, toque em Tornar dono ao lado do nome dela. Assim, se um de vocês trocar de celular, o outro continua podendo aprovar pessoas.

3.5Mande para a república

Mande só o link do app. Cada amigo instala, cria o próprio cardápio e manda o código para a namorada, igual aos passos 3.3 e 3.4. Cada cardápio só é visto por quem entrou com o código dele.

Se algo der errado

Configurações mostra “Banco desatualizado”
O app foi atualizado e precisa de uma versão mais nova do banco. Rode o SQL do passo 1.4 inteiro de novo: ele atualiza sem apagar nada. Até lá o app funciona normalmente, só sem as novidades que dependem do banco (como a opção “os dois”).
Tela “Falta configurar o app”
O config.js ainda está com COLE_AQUI ou a URL não começa com https://. Refaça o passo 2.4 e espere 1 minuto.
Tela “Falta um ajuste no Supabase”
O acesso anônimo está desligado. Refaça o passo 1.5.
Tela “Chave inválida”
A chave do config.js não é a Publishable key deste projeto. Copie de novo no passo 1.6, com cuidado para não sobrar espaço nem faltar letra.
Erro “permissão” ao criar o cardápio, ou tabelas não encontradas
O SQL não rodou inteiro. Volte ao passo 1.4 e rode de novo: ele pode ser rodado quantas vezes precisar.
O GitHub mostra “404 There isn’t a GitHub Pages site here”
Espere mais alguns minutos. Se continuar, confira se o index.html está na raiz do repositório (passo 2.3) e se o Pages está em main e / (root) (passo 2.5).
O app parou de carregar depois de uns dias sem uso
No plano grátis, o Supabase pausa o projeto depois de 7 dias sem uso e manda um e-mail avisando. Entre em supabase.com/dashboard, abra o projeto e clique em Resume project. Os dados continuam lá. Usando o app toda semana, isso não acontece.
Troquei de celular ou apaguei os dados do navegador
O app não tem login, então o celular novo vira uma pessoa nova. Entre de novo com o código e peça para editar. Se você era o único dono, peça para o outro dono aprovar; por isso vale tornar seu par dono também (passo 3.4).
Quero mudar o nome do app
Edite no GitHub (lápis): em manifest.webmanifest, os campos name e short_name; em index.html, a linha const APP_NAME = "Prato a Dois";, a tag <title> e a linha apple-mobile-web-app-title. Quem já instalou precisa remover o ícone e adicionar de novo para ver o nome novo.
Como atualizo o app depois?
Troque o arquivo no GitHub (lápis para editar, ou Add file → Upload files para substituir). O celular pega a versão nova na próxima vez que abrir o app, em alguns minutos.
