Prato a Dois · guia de implantação

Do zero ao app no celular em cerca de 30 minutos. Tudo no plano grátis.

0 de 0 passos

Marque cada passo quando terminar. O progresso fica salvo neste navegador, então dá para parar e voltar depois.

O que veio no zip
  • Os arquivos do app: index.html, logica.js, config.js, manifest.webmanifest, sw.js e os ícones .png. É isso que vai para o GitHub (o repositório oficial já tem tudo, inclusive as pastas docs e dev).
  • supabase.sql: o banco de dados. Ele também está no passo 1.4 com botão de copiar.
  • Este guia.

Faça as partes 1 e 2 num computador. A parte 3 é no celular.

Parte 1 · Banco de dados no Supabasecerca de 10 minutos

1.1Crie uma conta no GitHub (se ainda não tiver)

  1. Acesse github.com/signup.
  2. Preencha e-mail, senha e um nome de usuário. Guarde o nome de usuário: ele vai aparecer no link do app.
  3. Confirme o código que chega por e-mail.

Você vai usar essa mesma conta para entrar no Supabase.

1.2Entre no Supabase com o GitHub

  1. Acesse supabase.com/dashboard.
  2. Clique em Continue with GitHub e autorize.
  3. Se pedir para criar uma organização: dê qualquer nome (ex.: Miguel), tipo Personal, plano Free, e clique em Create organization.

1.3Crie o projeto

  1. Clique em New project.
  2. Project name: prato-a-dois.
  3. Database Password: clique em Generate a password e guarde a senha num lugar seguro. O app não usa essa senha, mas ela é sua chave mestra do banco.
  4. Region: South America (São Paulo).
  5. Clique em Create new project e espere uns 2 minutos até o painel do projeto aparecer.

1.4Crie as tabelas: cole o SQL e rode

  1. No menu da esquerda, clique em SQL Editor.
  2. Clique em + ou New query para abrir uma consulta em branco.
  3. Clique em Copiar SQL aqui embaixo, cole no editor (Ctrl+V ou Cmd+V) e clique em Run.
  4. Se aparecer um aviso de “destructive operation”, confirme em Run this query. É só porque o script recria as regras de acesso; nenhum dado é apagado.
Deu certo quando aparecer Success. No rows returned embaixo do editor.
supabase.sql
{{SQL}}

1.5Ligue o acesso sem login

O app não tem login: cada celular ganha uma identidade anônima. Isso precisa ser ligado:

  1. No menu da esquerda, clique em Authentication.
  2. Clique em Sign In / Providers.
  3. Ative Allow anonymous sign-ins.
  4. Clique em Save changes.
Se pular este passo, o app mostra a tela “Falta um ajuste no Supabase”.

1.6Copie a URL e a chave pública do projeto

  1. No topo do painel do projeto, clique em Connect.
  2. Copie a Project URL (algo como https://abcdefghijklmnop.supabase.co) e cole num bloco de notas.
  3. Copie a Publishable key (começa com sb_publishable_) e cole também.

Não achou o botão Connect? Vá em Project Settings (engrenagem) → API Keys para a chave, e em Data API para a URL. Em projetos antigos a chave pública se chama anon public: pode usar ela.

Nunca use a secret key (sb_secret_) nem a service_role. Elas ignoram as regras de acesso e não podem ir para o GitHub.

Parte 2 · Site no GitHub Pagescerca de 10 minutos

2.1Descompacte o zip no computador

Clique com o botão direito no zip e escolha Extrair tudo (Windows) ou dê dois cliques (Mac). Você vai usar a pasta site.

2.2Crie o repositório

  1. Entre em github.com/new.
  2. Repository name: prato-a-dois.
  3. Deixe marcado Public. O GitHub Pages grátis só funciona com repositório público. O código fica visível, mas os dados de vocês ficam protegidos no Supabase.
  4. Não marque README, .gitignore nem licença.
  5. Clique em Create repository.

2.3Envie os arquivos do app

  1. Na página do repositório vazio, clique no link uploading an existing file.
  2. Abra a pasta site no computador, selecione todos os arquivos de dentro dela (Ctrl+A ou Cmd+A) e arraste para a página. Arraste os arquivos, não a pasta.
  3. Espere todos os arquivos aparecerem na lista.
  4. Lá embaixo, clique em Commit changes.
Confira: a página do repositório precisa mostrar index.html direto na lista, não dentro de uma pasta site.

2.4Cole a URL e a chave no config.js

  1. No repositório, clique em config.js.
  2. Clique no ícone de lápis (Edit this file), no canto direito acima do código.
  3. Troque COLE_AQUI_A_PROJECT_URL pela Project URL e COLE_AQUI_A_PUBLISHABLE_KEY pela Publishable key. Mantenha as aspas.
  4. Clique em Commit changes... e depois em Commit changes de novo na janela que abrir.

Depois de editado, o miolo do arquivo fica assim (com os seus valores):

config.js (exemplo)
{{CONFIG_EXEMPLO}}

2.5Ligue o GitHub Pages

  1. No repositório, clique na aba Settings.
  2. No menu da esquerda, clique em Pages.
  3. Em Build and deployment → Source, escolha Deploy from a branch.
  4. Em Branch, escolha main e a pasta / (root).
  5. Clique em Save.

2.6Pegue o link do app e teste

  1. Espere 1 a 2 minutos e recarregue a página Pages.
  2. Vai aparecer Your site is live at com o link https://SEU-USUARIO.github.io/prato-a-dois/. Clique em Visit site.
  3. Deve abrir a tela vermelha do Prato a Dois perguntando Como você se chama?
Esse é o link do app. É ele que você manda para a namorada e para a república.
Apareceu outra tela? Veja “Se algo der errado” no fim deste guia.

Parte 3 · Instalar no celular2 minutos por pessoa

3.1Abra o link no navegador certo

  • iPhone: abra no Safari. Se o link abrir dentro do WhatsApp ou Instagram, toque em ⋯ ou no ícone de compartilhar e escolha Abrir no Safari.
  • Android: abra no Chrome.

No primeiro acesso, o próprio app mostra o tutorial de instalação.

3.2Adicione à tela de início

iPhone (Safari):

  1. Toque em ⋯ (três pontinhos) no canto de baixo, à direita. Se a barra mostrar o ícone de compartilhar (quadrado com seta), toque direto nele e pule o próximo item.
  2. Toque em Compartilhar.
  3. Toque em Adicionar à Tela de Início. Se não aparecer, toque em Ver mais ou role a lista.
  4. Deixe Abrir como App Web ligado e toque em Adicionar.

Android (Chrome):

  1. Toque em ⋮ (três pontinhos) no canto de cima, à direita.
  2. Toque em Instalar app (em alguns celulares: Adicionar à tela inicial).
  3. Confirme em Instalar.
No iPhone, instale antes de digitar o nome e criar o cardápio. O app instalado guarda os dados separado do Safari: o que for feito no Safari não aparece no app instalado.

Dá para ver esse tutorial de novo a qualquer hora: Configurações → Como instalar no celular.

3.3Crie o cardápio de vocês

  1. Abra o Prato a Dois pelo ícone na tela de início.
  2. Digite seu nome e toque em Começar.
  3. Toque em Criar cardápio novo, dê um nome e toque em Criar cardápio.
  4. Toque em Compartilhar (ou Enviar pelo WhatsApp) para mandar o link e o código de 5 caracteres para sua namorada.

3.4Libere a edição para o seu par

  1. Ela instala o app, digita o nome, toca em Entrar com código e digita o código.
  2. Ela entra como leitora e toca em Pedir para editar.
  3. No seu celular aparece o aviso de pedido. Toque nele (ou em Configurações) e em Aprovar.
  4. Recomendado: em Configurações → Pessoas, toque em Tornar dono ao lado do nome dela. Assim, se um de vocês trocar de celular, o outro continua podendo aprovar pessoas.

3.5Mande para a república

Mande só o link do app. Cada amigo instala, cria o próprio cardápio e manda o código para a namorada, igual aos passos 3.3 e 3.4. Cada cardápio só é visto por quem entrou com o código dele.

Se algo der errado

Configurações mostra “Banco desatualizado”
O app foi atualizado e precisa de uma versão mais nova do banco. Rode o SQL do passo 1.4 inteiro de novo: ele atualiza sem apagar nada. Até lá o app funciona normalmente, só sem as novidades que dependem do banco (como a opção “os dois”).
Tela “Falta configurar o app”
O config.js ainda está com COLE_AQUI ou a URL não começa com https://. Refaça o passo 2.4 e espere 1 minuto.
Tela “Falta um ajuste no Supabase”
O acesso anônimo está desligado. Refaça o passo 1.5.
Tela “Chave inválida”
A chave do config.js não é a Publishable key deste projeto. Copie de novo no passo 1.6, com cuidado para não sobrar espaço nem faltar letra.
Erro “permissão” ao criar o cardápio, ou tabelas não encontradas
O SQL não rodou inteiro. Volte ao passo 1.4 e rode de novo: ele pode ser rodado quantas vezes precisar.
O GitHub mostra “404 There isn’t a GitHub Pages site here”
Espere mais alguns minutos. Se continuar, confira se o index.html está na raiz do repositório (passo 2.3) e se o Pages está em main e / (root) (passo 2.5).
O app parou de carregar depois de uns dias sem uso
No plano grátis, o Supabase pausa o projeto depois de 7 dias sem uso e manda um e-mail avisando. Entre em supabase.com/dashboard, abra o projeto e clique em Resume project. Os dados continuam lá. Usando o app toda semana, isso não acontece.
Troquei de celular ou apaguei os dados do navegador
O app não tem login, então o celular novo vira uma pessoa nova. Entre de novo com o código e peça para editar. Se você era o único dono, peça para o outro dono aprovar; por isso vale tornar seu par dono também (passo 3.4).
Quero mudar o nome do app
Edite no GitHub (lápis): em manifest.webmanifest, os campos name e short_name; em index.html, a linha const APP_NAME = "Prato a Dois";, a tag <title> e a linha apple-mobile-web-app-title. Quem já instalou precisa remover o ícone e adicionar de novo para ver o nome novo.
Como atualizo o app depois?
Troque o arquivo no GitHub (lápis para editar, ou Add file → Upload files para substituir). O celular pega a versão nova na próxima vez que abrir o app, em alguns minutos.
